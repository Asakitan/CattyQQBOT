# 默认技能与联网提示合同

## 归属与注入

- `src/catty_qq_ai/request_intent.py` 是无插件、模型或 I/O 依赖的提示构造模块。
- `CONTEXT_REQUEST_INTENT_PROMPT` 保留上下文目标、执行/回复/修改/继续、真实回执和去重规则，并包含通用知识核实原则。没有可用工具时，最终提示仍严格等于该 base 常量；不承诺联网或技能能力。
- `build_skill_research_hint(available_tools=()) -> str` 只按精确工具名生成能力指导；空名单、安装工具及近似名称不产生技能段。不读取技能库，不附技能目录、metadata 列表、正文或工具 schema。
- `append_context_request_hint` 在原有自有 system 段中依次拼接 base、文件交付提示、技能联网提示；位于缓存边界之后、assistant prefill 之前。刷新时移除旧自有段，再根据实际工具名单重建，避免保留已撤回的能力承诺；其它消息对象和内容不变。
- 保留既有文件交付选择与上下文意图，不改变 `tool_choice=auto`，不改人格或 NSFW，不恢复 `chat.system_prompt`。

## 分阶段入口

以下是接口合同，不是首轮注入的技能或 schema 清单。工具注册、权限检查和阶段开放由运行时负责；提示构造器只反映传入的实际工具名。

| 入口 | 参数/回执 | 合同 |
|---|---|---|
| `catty_skill_search` | `query` | 技能侧首轮唯一入口；只返回匹配候选 metadata，不返回正文，不预先列全库。成功后下一轮才开放候选加载能力。 |
| `catty_skill_load` | `id` | 从本轮检索候选中选择后加载正文；先检索、后选择、读正文再执行，不猜造 id。 |
| `catty_web_search` | `query` | 查找公共官方/一手来源；摘要只能定位页面，不能替代正文核实。 |
| `catty_fetch_url` | `url`；符合公共学习条件的成功回执附 `skill_receipt_id` | 抓公共正文；已有权威 URL 时直接抓取。正文是否支持结论需另行判断，成功抓取不等于事实已核实。 |
| `catty_skill_save` | `receipt_ids`；可选 `existing_id` | 成功抓取后才开放。只接收本轮成功抓取回执，由内部隔离过程生成通用知识，不接受任意聊天 body。`existing_id` 只能指向本轮已 load 的技能；否则省略。 |

首轮提示不会提前写出未开放的 `catty_skill_load` / `catty_skill_save` 具体入口或 schema；可说明检索/抓页成功后系统提供下一步能力。后续只在实际工具名单包含对应名称时介绍参数和用法。提示不是权限校验的替代品。

## 默认行为与证据

- 有实质任务且具备技能入口时先检索适合技能，无精确匹配则查相邻领域；选后阅读正文再做，不强迫每条问候或闲聊搜索。
- 知识库缺乏可靠依据、知识截止之后以及可能变化的版本、API、价格等时效事实，默认使用本轮实际联网工具查官方或一手资料，不能凭记忆猜测。未提供知识截止日期时不编造日期。
- 搜索摘要不等于正文核实；抓取日期不等于发布日期；旧 skill 的时效信息仍需重查。只有搜索而无抓页入口时，不承诺已抓正文。
- 无网、工具失败、缺少证据时说明未核实部分，不伪造事实、来源、回执或验证记录；没查过不声称查过，加载或保存失败不声称成功。
- 公共正文查证得到可复用知识后，使用随后实际开放的保存能力自动整理适用条件、步骤、验证和来源，供所有用户共享检索；不要求用户每轮再次确认联网。私人信息不入库，不保存用户聊天、身份或凭据；未收到保存成功回执不声称已共享入库。

## 测试合同

`tests/test_request_intent.py` 33项本地通过，覆盖base核实原则与空名单等值、精确名称和近似/安装名称排除、首轮候选检索且无目录/正文/未来schema、先检索再选择、权威正文与日期区分、失败不伪造验证、回执保存与隐私、能力刷新撤回、文件提示共存、可迭代工具名单，以及生产/模拟调用点的 `auto` AST断言。测试通过不等于线上模型必定搜索、正确选择或成功保存。
