# 日志触发与脱敏

`LogMonitor` 按 `self_repair.log_paths` 读取 `logs/` 下的 Loguru 格式文件。默认主日志及守护日志；只有真实行首级别 WARNING、ERROR、CRITICAL 触发，INFO 正文里的这些词不会触发。异常堆栈归并到同一事件；Loguru 的局部变量值块被移除。

每轮读取受 `max_log_bytes` 限制；首次只看 `initial_tail_bytes` 尾部，设为 0 则只看新日志。游标记录文件身份、字节位置和边界摘要，处理文件替换、截断及截断后再增长。未完成的原始行不写入状态文件，只记录摘要并从原文件重读；超长物理行省略内容并推进游标。

故障指纹归一时间、行号、请求 ID 等变化，保留 HTTP/系统错误码。去重次数、待处理事件和冷却记录持久化，`debounce_seconds` 合并故障，`cooldown_seconds` 限制重复任务；一轮只交出配置的事件数，其余保留。状态文件损坏时暂停，不当成初次启动重放所有日志。

选中事件先持久写入游标与冷却，再交给模型工作进程，因此是最多一次交接：提交后、模型请求前的进程退出可能使该事件等待新的日志或手动升级请求，并不是恰好一次执行。

已知配置凭据、常见 API key/token、Bearer/Basic、Cookie、URL 用户信息和查询参数会被替换。此处理不是通用个人信息识别器；日志中其它业务内容仍可能发送到配置的修复 LLM。修复器自身状态写入 `data/self_repair/`，不回灌主日志触发自身修复。
