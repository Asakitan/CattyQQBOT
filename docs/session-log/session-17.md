# 会话 17 · 自修复缺省主 AI 与部署

## 目标与范围

- 自修复模型缺省时使用主 AI 的模型、端点、密钥和代理；明确配置独立修复模型时保持独立，不在请求失败后自动切线。
- 周预算继续独立，保持原有候选验证、启动观察和回滚流程。用户要求完成后推送生产；默认启用开关保持关闭。

## 已完成

- `RepairConfig` 在启用且修复模型为空或 `TARGET` 时解析主 AI 路由；主路由变化纳入配置指纹。
- 修复器支持 Chat Completions 和无状态 Responses 工具调用，后者保留加密推理项；支持显式 HTTP/SOCKS 代理。
- 已下载生产无密钥的共享代码基线，核对自修复范围；不复制或输出真实生产密钥。
- 修复 Responses 成功回执的 `error:null` 误判；非空错误仍阻断工具并按保守预留结算。
- 远端 Python venv 启动器产生真实解释器子进程；监督器通过 Windows 系统进程快照确认直接父子关系，拒绝无关 PID。验证子进程统一使用解析后的临时目录路径，避免 8.3 短路径造成假回归。
- 为避免生产旧守护在依赖未全部上传时自重启，先推 23 个源码、配置模板及测试，再单独推守护文件。初次变更被旧守护的 bot 重启快照合并后，仅更新守护文件时间戳触发既有自重启，字节未改。

- 本地自修复与相关回归共 255 项通过，含默认继承、显式模型不混用、主 AI 变更阻断、`error:null`、SOCKS 代理和 4 项真实子进程升级/回滚验收。
- 远端 Python 3.14 隔离包 195 项通过；部署后生产目录的配置、模型、worker、监督器和相关回归 160 项通过。
- 生产源码复制到不含 `config.json` 的隔离仓库，叠加验收包后冻结 428 文件，基线与候选各运行 191 项默认测试并通过结果比对；两个缺真实配置引起的基线错误如实保留。隔离快照未改生产源码。
- 生产主 AI 经 SOCKS 代理发送两轮合成工具协议请求，均 HTTP 200，分别使用 344、395 token；只提供合成工具回执，没有执行工具或发送真实日志。该次响应无推理项，加密推理回放由离线夹具覆盖。
